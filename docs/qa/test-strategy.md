## 1. Цели качества

Главный риск продукта - **потеря или дубль публикации**. Стратегия подчинена этому риску и NFR из `00-overview.md`.

| Цель | Метрика / критерий |
|---|---|
| Публикации без потерь и дублей | 0 потерянных, 0 задублированных (at-least-once + идемпотентность) |
| Своевременность | p95 ≤ 20 с, **p99 ≤ 60 с** от `scheduled_at` при пике **2 000 пуб./с** |
| Масштаб | 100 000 пользователей с запасом ×3 (300 000); до 1 500 000 каналов; 5 млн пуб./сутки |
| Доступность | API/веб 99.9 %/мес; контур публикаций 99.95 % |
| Регрессия | ключевые пути автоматизированы на каждом PR / merge |
| Безопасность | 0 критических уязвимостей OWASP Top 10 / API Top 10 на релизе |
| Покрытие автотестами P0-кейсов | ≥ 90 % к гейту релиза MVP |
| Flaky-тесты | доля < 2 %; карантин ≤ 1 спринт |

**Качество продукта vs Впостер:** дифференцируем надёжностью (SLA публикации, алерты, восстановление без потерь) - см. `docs/analysis.md` §6 п.3 и §8.2 п.5.

## 3. Пирамида тестов

```
                    ┌─────────────────┐
                    │  Хаос / DR / L* │  staging, перед релизом
                    ├─────────────────┤
                    │  E2E / Smoke    │  merge + nightly + после деплоя
                    ├─────────────────┤
                    │ Контракт / Arch │  каждый PR
                    ├─────────────────┤
                    │  Интеграция     │  каждый PR (Testcontainers)
                    ├─────────────────┤
                    │     Unit        │  каждый PR
                    └─────────────────┘
```

| Уровень | Кто пишет | Инструменты | Где запускается | Цель |
|---|---|---|---|---|
| Unit (домен, лимиты сетей, рендер, повторы, биллинг) | Бэк/Фронт; QA ревьюит покрытие | **JUnit 5** + AssertJ + Mockito, JaCoCo; Vitest + Testing Library | каждый PR | быстрая обратная связь, покрытие домена ≥ 80 % |
| Интеграционные (репозитории, Flyway, RabbitMQ, scheduler/publisher, Redis-лимиты) | Бэк + QA | JUnit 5 + **Testcontainers** (`@ServiceConnection`: Postgres, Redis, RabbitMQ, MinIO), Awaitility, Spring Boot Test | каждый PR (`./gradlew integrationTest`) | реальные зависимости без моков инфраструктуры |
| Контрактные API (OpenAPI ↔ реализация) | QA | **Schemathesis** по `docs/api/openapi.yaml`, oasdiff | каждый PR / ночью | property-based соответствие контракту |
| Контрактные адаптеров соцсетей | Бэк + QA | **WireMock**, JSON-фикстуры (ошибки, таймауты) | каждый PR | стабильные сценарии API сетей |
| Архитектурные правила | Бэк; QA контролирует | ArchUnit | каждый PR | границы модулей Gradle |
| Фикстуры форматирования (`docs/api/fixtures/formatting`) | QA ведёт набор | JUnit (бэк-рендер) + Vitest (фронт-предпросмотр) | каждый PR | паритет TG/Max HTML и предпросмотра |
| E2E UI | QA | **Playwright** (Chromium, WebKit, mobile viewport), MSW или sandbox-каналы | merge в `main` + ночью | критические пользовательские пути |
| Smoke staging/prod (реальные тестовые каналы) | QA | Playwright + API-скрипты | после деплоя + каждые 30 мин | синтетика «живой» публикации |
| Нагрузочные | QA + Devops | **k6** (+ k6-operator), эмулятор соцсетей | перед релизом, еженедельно ночью на staging | пик 2 000/с, soak, stress |
| Хаос / отказоустойчивость | QA + Devops | Chaos Mesh / ручные сценарии | перед релизом, ежеквартально | 0 потерь/дублей при отказах |
| Безопасность | QA (+ Devops: Trivy/CodeQL) | OWASP ZAP baseline, IDOR/RBAC, gitleaks | CI + перед релизом | OWASP Top 10 / API Top 10 |
| a11y и perf фронта | QA + Фронт | axe-core в Playwright, Lighthouse CI | merge в `main` | нет критичных a11y; Lighthouse a11y ≥ 90 на layout |

### 3.1. Эмулятор соцсетей (`tests/social-emulator`)

Обязательный стенд для e2e, нагрузки и хаоса (совместно с Бэком, QA-3):

- имитация VK / Telegram Bot API / OK / Max;
- настраиваемые задержки, 5xx, 429 + `retry_after`, ошибки VK 6/9/10/15/100, таймауты, «успех без ответа»;
- учёт созданных постов и API сверки дублей;
- Docker-образ в compose и на staging.

## 4. Окружения

| Окружение | Назначение | Данные | Соцсети |
|---|---|---|---|
| **local** | разработка и unit/интеграция | seed `R__seed_local.sql`, Mailpit | эмулятор / WireMock |
| **CI** | PR-гейты | эфемерные контейнеры Testcontainers / compose | WireMock, эмулятор в nightly |
| **staging** | e2e, нагрузка, хаос, security, регрессия story | обезличенные/синтетические; seed объёмов для L* | эмулятор + **реальные тестовые каналы** (VK/TG/OK/Max) для smoke |
| **production** | только синтетика / мониторинг | прод | только выделенные тестовые каналы платформы; без разрушающих сценариев |

Правила:

- Секреты - только через Vault/ENV, не в репо и не в отчётах.
- Нагрузка L1–L6 и хаос - **только staging** с прод-подобными ресурсами (`04-devops.md`).
- После деплоя на staging - обязательный smoke; на prod - синтетика каждые 30 мин.

## 5. Процесс и shift-left

1. **Груминг:** QA участвует; каждая story получает тест-кейсы (или ссылки на TC) до старта разработки; AC проверяются на тестируемость.
2. **В спринте:** автотесты пишутся вместе с фичей; flaky → карантин + тикет, исправление ≤ 1 спринт.
3. **PR:** unit + integration + ArchUnit + contract (по зоне); ревью покрытия и негативных сценариев.
4. **Merge в main:** e2e smoke; ночной полный e2e + Schemathesis + отчёт в Telegram команды.
5. **Перед релизом:** полный авторегресс + exploratory 2 ч по чартерам (редактор, календарь, биллинг, мобильный вид) + L1–L6 + хаос/DR + security-чеклист + restore из бэкапа.
6. **После релиза:** метрики escaped defects, покрытие P0 автотестами, время CI, доля flaky.

Ветки/коммиты: Conventional Commits; задача QA → ветка по `agent-tasks.md`; зона правок - `docs/qa/` и `tests/` (CODEOWNERS).

## 6. Критерии входа и выхода

Подробная матрица severity/priority - в [defect-classification.md](defect-classification.md).

### 6.1. Вход в тестирование story / фичи

- AC согласованы (Definition of Ready из `01-analyst.md`), приоритет P0–P2 назначен.
- Сборка задеплоена на **staging** (или доступен воспроизводимый local/compose для интеграционных проверок).
- Unit и интеграционные тесты зоны **зелёные** в CI.
- Есть тест-кейсы (или черновик TC) со ссылкой на story; для API - актуальный `openapi.yaml`.
- Нет открытых Blocker в той же зоне, блокирующих сценарий.

### 6.2. Выход из тестирования story

- Все TC приоритета P0 по story пройдены (авто или ручные с отчётом).
- Нет открытых Blocker/Critical по story.
- Major - либо исправлены, либо приняты владельцем с обходным путём и тикетом.
- Автотесты на P0-сценарии добавлены или запланированы тикетом с датой ≤ следующий спринт (исключение: явно «ручной» TC).

### 6.3. Выход (релиз MVP) - гейт релиза

Из `05-qa.md` §4 и `00-overview.md` §6:

| Критерий | Порог |
|---|---|
| P0-кейсы | **100 %** пройдено |
| Открытые дефекты | **0** Blocker / Critical; **≤ 5** Major с обходным путём и согласием владельца |
| Нагрузка | сценарии L1–L6 (§7) пройдены на staging |
| Хаос / DR | сценарии §8 пройдены; restore из бэкапа отрепетирован (RPO ≤ 5 мин, RTO по спеке) |
| Безопасность | ZAP baseline без Critical; IDOR/RBAC-матрица без провалов P0; нет утечек токенов в логах |
| a11y | нет критичных нарушений axe; layout Lighthouse a11y ≥ 90 |
| Наблюдаемость | алерты публикаций/API работают (проверены тестовым инцидентом) |
| Отчёт | `docs/qa/release-report-vX.md` заполнен и согласован |

### 6.4. Критерии отмены / стоп-шип

- p99 задержки публикации > 60 с на staging в L2 без понятного плана фикса до релиза;
- обнаружены потери или дубли публикаций в конвейере;
- недоступность входа/оплаты (Blocker) без фикса;
- исчерпан error budget SLO - только работы по надёжности (`04-devops.md` §6).

## 7. Нагрузочное тестирование

Инструмент: **k6** (`tests/load`, k6-operator в K8s). Цель - подтвердить NFR при эмуляторе соцсетей на staging.

| ID | Сценарий | Профиль | Критерии прохождения |
|---|---|---|---|
| L1 | API смешанный | 10 000 VU, 5 000 RPS: 60 % чтение календаря/списков, 20 % create/edit постов, 10 % media-presign, 10 % прочее; 30 мин | p95 чтение ≤ 300 мс, запись ≤ 500 мс; ошибки < 0.1 % |
| L2 | Пик публикаций | 1 500 000 каналов в БД; 120 000 пуб. на одну минуту (2 000/с); 3 «ровных часа» подряд | p99 задержки ≤ 60 с; **0 потерь, 0 дублей** (сверка эмулятора ↔ БД); очередь ≤ 2 мин |
| L3 | Soak | 30 % от пика, 8 ч | нет утечек памяти; стабильная латентность; рост БД предсказуем |
| L4 | Stress | рост до ×2 пика | контролируемая деградация (очереди↑, API 429/503, без падения); автовосстановление |
| L5 | Вебхуки ingest | 5 000 соб./с (VK Callback / TG) | handler p99 ≤ 100 мс; без потерь |
| L6 | Объём данных | 300 000 пользователей, 50 млн publications | календарь ≤ 300 мс p95 (индексы/партиции) |

**Отчёт:** графики Grafana, узкие места, тикеты на оптимизацию. Повтор - перед каждым мажорным релизом и после изменений конвейера.

Минимальный набор кейсов конвейера для автоматизации (см. `05-qa.md` §5): TC-PUB-01…13 - идемпотентность, ретраи, 429, failover PG/RabbitMQ, изоляция сетей, WS-статусы ≤ 3 с.

## 8. Хаос и аварийное восстановление

Совместно с Devops (`tests/chaos`, Chaos Mesh / runbook’и):

| Сценарий | Ожидание |
|---|---|
| Убийство случайных подов publisher / scheduler / api в пике | задача доработана; **0 дублей, 0 потерь** |
| Отказ узла K8s / целой зоны | RTO ≤ 1 ч; публикации восстанавливаются |
| Failover PostgreSQL в пике | 0 потерь, 0 дублей; задержка зафиксирована |
| Рестарт узла RabbitMQ (quorum) | сообщения сохранены; просроченные догоняются |
| Недоступность Redis rate-limit | консервативный локальный лимит; без шторма к соцсетям |
| Сетевая задержка 500 мс к «соцсети» | ретраи/таймауты корректны; изоляция сетей |
| PITR «5 мин назад» + сверка | повторная обработка без дублей; RPO ≤ 5 мин |

Учения: restore бэкапа - ежемесячно (автоjob); полный DR - ежеквартально. Результаты - в `docs/qa/release-report-*` и runbook’ах.

## 9. Безопасность (чеклист перед релизом)

- OWASP ZAP baseline + активное сканирование staging;
- матрица IDOR/RBAC (автогенерация из `roles-permissions.md`);
- JWT: `alg=none`, подмена, истёкшие токены; CSRF на cookie-эндпоинтах;
- XSS в тексте поста / предпросмотре / комментариях / именах каналов;
- SSRF в URL-полях (RSS, картинка по ссылке);
- загрузка файлов: polyglot, SVG со скриптом, zip-бомба, oversized;
- rate limits auth и API;
- поиск утечек токенов соцсетей в логах/ответах; проверка envelope/KMS в БД;
- security-заголовки; Trivy/CodeQL/gitleaks зелёные.

## 11. Метрики качества

| Метрика | Цель |

## 12. Риски стратегии и митигация

| Риск | Митигация |
|---|---|
| Эмулятор ≠ реальное API сети | smoke на реальных тестовых каналах; контрактные фикстуры с записью ответов |
| Flaky e2e из-за таймингов публикаций | Awaitility/явные условия по WS/API; запрет `waitForTimeout` без причины |
| Нагрузка на staging дорога/редка | еженедельный урезанный L1+L2 smoke; полный L* перед релизом |
| Пробелы в AC | ревью тестируемости на груминге; возврат story Аналитику |
| Дубли только «на бумаге» | обязательная сверка эмулятор ↔ `publications` / `publication_attempts` в TC-PUB и L2 |
