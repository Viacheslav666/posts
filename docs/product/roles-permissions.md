## 1. Роли workspace

| Роль | ID | Назначение |
|---|---|---|
| **Owner (Владелец)** | `owner` | Биллинг, удаление workspace, полный контроль. Ровно один Owner на workspace (передача владения — отдельная операция). |
| **Admin (Админ)** | `admin` | Участники, роли, каналы, публикации; без биллинга и удаления workspace. |
| **Editor (Редактор)** | `editor` | Создаёт, планирует и публикует в назначенных проектах; может согласовывать. |
| **Author (Автор)** | `author` | Создаёт черновики и отправляет на согласование; **не** планирует/публикует сам. |
| **Viewer (Наблюдатель / Клиент)** | `viewer` | Чтение назначенных проектов; комментарии; согласование, если включено «клиент согласует». |

Отдельная роль «Аналитик» в MVP **не вводится** (аналитику смотрят Editor+; Author — свои посты; Viewer — свои проекты). При необходимости — Фаза 2.

Системная роль **platform_admin** (внутренняя админ-панель E7) — вне матрицы workspace; доступ по отдельному флагу аккаунта.

## 2. Области действия (scope)

| Scope | Правило |
|---|---|
| `workspace` | Операция на уровне всего workspace. |
| `assigned_projects` | Только проекты из `ProjectGrant` участника. |
| `own_posts` | Только посты, где пользователь — автор (`created_by`). |
| `billing` | Только Owner. |

**Изоляция:** любой доступ к чужому `workspace_id` → **404** (не 403), чтобы не раскрывать существование ресурса (IDOR).

**Owner и Admin** видят все проекты workspace без явных grant.  
**Editor / Author / Viewer** — только назначенные проекты; канал/пост чужого проекта → 404.

## 5. Контракт YAML для автотестов

Файл `roles-permissions.yaml`:

- `version` — semver матрицы; при breaking-изменении прав — major.
- `roles[]` — стабильные ID ролей.
- `actions[]` — стабильные ID действий (`resource.verb`).
- `matrix[]` — каждая строка: `action`, `effect` на роль (`allow` \| `deny`), опционально `scope` и `conditions`.
- Генератор тестов (QA-6) для каждой пары `(role, action)` с `effect: allow` ожидает **2xx** на разрешённом ресурсе в scope; с `deny` — **403** на своём workspace и **404** на чужом.
- Бэк (BE-6) мапит `action` → `@PreAuthorize` / `PermissionEvaluator`.

Изменение матрицы — только через PR Аналитика в `docs/product/`; Бэк и QA подтягивают тот же YAML.
