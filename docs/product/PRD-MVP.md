## 1. Цель продукта (MVP)

Дать SMM-фрилансерам, агентствам и бизнесу в РФ **надёжный планировщик публикаций для команды**: один редактор — несколько сетей (VK, Telegram, OK, Max), гарантированный выход поста вовремя (или мгновенное уведомление об ошибке без потери и без дублей), роли и проекты, базовый биллинг и аналитика публикаций.

**Обещания MVP (из видения продукта):**
1. Пост выйдет вовремя (p99 ≤ 60 с от `scheduled_at`) или пользователь узнает об этом сразу; пост не теряется и не дублируется. **★**
2. Команда работает в одном workspace с ролями и проектами. **★**
3. Один редактор — все сети MVP, с предпросмотром и валидацией лимитов. **★**
4. Базовая прозрачность: статусы по каждому каналу, аудит, уведомления об ошибках. **★**

---

## 2. Проблема и возможность

Впостер силён ценой и VK-утилитами, но слабо закрывает:
- командную работу и согласование;
- визуальный контент-календарь и варианты поста под сеть;
- кросс-сетевую надёжность и SLA публикаций;
- вход не только через VK ID;
- сегментированные тарифы (фрилансер / агентство / бизнес).

Posts на MVP забирает ядро постинга (паритет) и закрывает эти пробелы как дифференциаторы. Полный паритет VK-автоматизаций (предложка, антиспам, граббер, боты и т.д.) — **Фаза 2–3**, не MVP.

## 6. Модель продукта (кратко)

```
Account → Workspace(s) → Project(s) → Channel(s)
                      ↘ Member(role) + project grants
Post → PostVariant(network) → Publication(channel) → attempts
ChannelSet → channels[]
Plan / Billing → limits (channels, seats, posts, AI credits)
```

Термины — в `glossary.md`. Права — в `roles-permissions.md` / `.yaml`.

**Правила доступа (MVP):**
- Все данные изолированы по `workspace_id` (чужой workspace → 404, не 403, против IDOR).
- Участник видит только **назначенные проекты** (кроме Owner/Admin — весь workspace).
- Author создаёт черновики; планирование/публикация без согласования — только Owner/Admin/Editor.
- Viewer (клиент) — чтение назначенных проектов; согласование — когда включено «клиент согласует» (полноценный UX — Фаза 2; право заложено в матрице).

|---|---|---|---|---|---|

**★** vs Впостер: сегментация тарифов, годовая скидка, места в команде, AI-квота в тарифе (использование AI — Фаза 2, квота уже в биллинге MVP).

## 8. Критерии приёмки релиза MVP (гейт релиза)

1. Все P0 stories E1–E6 приняты (Definition of Done из `00-overview.md`).
2. e2e зелёные; RBAC-матрица из `roles-permissions.yaml` гоняет автотесты (QA-6).
3. Нагрузочный тест **2 000 публикаций/с** на staging пройден; p99 ≤ 60 с.
4. Хаос: повторная доставка из очереди и убийство publisher mid-flight → **0 дублей**, пост не потерян.
5. Восстановление из бэкапа отрепетировано; алерты работают.
6. Документы product актуальны; OpenAPI соответствует stories (AN-4).
