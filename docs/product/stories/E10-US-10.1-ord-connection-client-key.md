## Ценность

**Как** Owner/Admin workspace, **я хочу** подключить свой API-ключ VK ОРД и/или ОРД Яндекса, **чтобы** маркировать рекламу без субсидирования ОРД со стороны Posts.

## Критерии приёмки (Given / When / Then)

1. **Given** Owner/Admin, workspace без ОРД
   **When** сохраняет connection `vk_ord` с API-ключом, ИНН издателя и ролями
   **Then** ключ хранится зашифрованно; статус `active` после успешного test; в UI не показывается plaintext ключа
2. **Given** тот же workspace
   **When** подключает `yandex_ord` аналогично
   **Then** оба провайдера полноценны (не stub); можно переключать default для постов
3. **Given** невалидный ключ / ОРД 401
   **When** нажимает «Проверить»
   **Then** статус error; код `ord_validation_failed` / понятное сообщение; публикации не затрагиваются
4. **Given** Editor
   **When** пытается изменить ORD connection
   **Then** 403; CRUD contractors ему доступен по матрице, connection - только Owner/Admin
5. **Given** продукт
   **When** любой сценарий биллинга ОРД
   **Then** Posts **не** выставляет и **не** субсидирует стоимость ОРД (решение Q-ORD-06)

## Тестовые данные (черновик для Тестировщика)

- Sandbox/WireMock ORD VK + Yandex
- Валидный и невалидный API-ключ
- ИНН издателя 10/12 цифр
