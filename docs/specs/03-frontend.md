# 03. ТЗ для агента «Posts Разраб Фронт» (веб-приложение)

Прочитать: `00-overview.md`, `01-analyst.md`, `02-backend.md` (раздел 7 «API»). Код: `frontend/` (pnpm workspaces): `frontend/apps/web`, `frontend/packages/ui`, `frontend/packages/api-client`, `frontend/packages/domain`. Бэкенд — Java 21 / Spring Boot (отдельно, в `backend/`); контракт API генерируется бэкендом в `docs/api/openapi.yaml`.

## 1. Стек и решения
- **Next.js 15 (App Router) + React 19 + TypeScript strict.** Публичные страницы (лендинг, тарифы, блог, документация, AdsMarket/анонимные страницы в Фазе 3) — SSR/SSG для SEO; приложение `/app/*` — клиентский рендер за авторизацией.
- Стили и компоненты: **Tailwind CSS + shadcn/ui (Radix)** в `packages/ui`, иконки lucide-react, тёмная/светлая тема (CSS-переменные, `prefers-color-scheme` + переключатель).
- Данные: **TanStack Query** (кэш, оптимистичные обновления, инвалидация по WS-событиям), типизированный клиент `frontend/packages/api-client`, генерируемый из `docs/api/openapi.yaml` (`openapi-typescript` → типы, `openapi-fetch` → клиент; скрипт `pnpm gen:api`, CI проверяет, что сгенерированный код совпадает с контрактом — руками не правится), **zod** для форм (react-hook-form + zodResolver). Лимиты и опции сетей берутся из `GET /api/v1/networks/capabilities` (кэш TanStack Query) — фронт валидирует для удобства, бэкенд (Java) — авторитетно.
- Локальное состояние: Zustand (редактор, UI-настройки).
- Календарь: **FullCalendar** (month/week/day/list) или собственный на dnd-kit — решить ADR после прототипа (критерий: 2 000 событий в месяце без лагов, drag&drop, кастомный рендер карточки).
- Редактор текста: **Tiptap** (ProseMirror) с расширениями под форматирование TG/Max, эмодзи, упоминания переменных; конвертер Tiptap JSON → TG HTML / Max HTML / plain (VK/OK) для **мгновенного предпросмотра** — в `frontend/packages/domain`; авторитетный рендер делает бэкенд (`POST /api/v1/posts/preview`, Java `libs/content`). Оба реализуются против общих эталонных фикстур `docs/api/fixtures/formatting/*.json` (Vitest-тест прогоняет все фикстуры) — расхождения ловятся в CI.
- Загрузка файлов: Uppy/tus-подобный multipart в S3 по presigned URL, параллельно, с резюмированием.
- Real-time: WebSocket (STOMP, `@stomp/stompjs`; бэкенд — Spring WebSocket) — статусы публикаций, уведомления, присутствие при совместном редактировании (Фаза 2).
- i18n: next-intl (ru по умолчанию, en подготовить), даты — date-fns-tz в TZ пользователя.
- PWA: manifest, service worker (Workbox) — офлайн-оболочка, Web Push.
- Мокирование: **MSW**-хендлеры, типизированные по `docs/api/openapi.yaml` (бэк публикует контроллеры-заглушки с финальными DTO заранее), для разработки параллельно с бэком; Storybook для `packages/ui`.
- Сборка/деплой: `next build` с `output: 'standalone'`, Dockerfile `frontend/apps/web/Dockerfile` (node:22-alpine, non-root); API доступен через тот же домен (`/api/*` → Ingress → posts-api), чтобы cookie refresh-токена были first-party.
- Аналитика продукта: Яндекс.Метрика (с согласия cookie) + собственные события в API.

## 2. Требования к качеству
- Core Web Vitals (p75): LCP ≤ 2.5 с, INP ≤ 200 мс, CLS ≤ 0.1; бандл первой загрузки приложения ≤ 250 КБ gzip (code splitting по маршрутам, ленивые календарь/редактор).
- Доступность WCAG 2.1 AA: клавиатурная навигация (в т.ч. календарь и редактор), фокус, aria, контраст.
- Адаптив: 360 px (мобильный) → 1920 px; мобильный UX — приоритет для календаря-списка, согласования и быстрого создания поста.
- Устойчивость: глобальные error boundaries, повтор запросов, индикатор офлайна, автосохранение черновика каждые 5 с + локальная копия в IndexedDB (восстановление после закрытия вкладки), предупреждение `beforeunload`.
- Безопасность: никаких токенов в localStorage (refresh — httpOnly cookie, access — в памяти), санитизация HTML предпросмотра (DOMPurify), CSP-совместимость.

## 3. Карта экранов
### Публичная часть
1. Лендинг (преимущества против конкурентов, сети, тарифы, отзывы, FAQ, CTA «7 дней бесплатно»).
2. Тарифы (калькулятор: каналы, места, год/месяц).
3. Вход / Регистрация / Подтверждение email / Восстановление пароля / 2FA-шаг; кнопки VK ID, Яндекс ID.
4. Приглашение в workspace (принять/создать аккаунт).
5. Публичная страница согласования поста для клиента (Фаза 2, без логина, по токену).
6. Status-страница (ссылка на внешний сервис статуса, его поднимает Devops).

### Приложение `/app`
Шапка: переключатель workspace → проект, глобальный поиск (⌘K), кнопка «Создать пост», уведомления, профиль. Боковое меню: Календарь, Посты (список), Каналы, Медиатека, Аналитика, Инбокс (Ф2), Автоматизации (Ф2), Реклама/ОРД (Ф2), Команда, Настройки, Биллинг.

## 4. Архитектура фронта
```
frontend/apps/web/src/
  app/(public)/...      app/(auth)/...      app/app/[workspace]/...
  features/<feature>/{api,components,hooks,model}   # calendar, editor, channels, media, billing, team, notifications
  entities/<entity>/                                # post, channel, workspace, user — типы, карточки, бейджи
  shared/{api-client,lib,config,ui}                 # обёртка клиента, ws, i18n, утилиты дат
```
- Ключи запросов TanStack Query — фабрика в `shared/api-client/keys.ts` (обёртка над `@posts/api-client`); WebSocket — STOMP-клиент (`@stomp/stompjs`) к `/ws` бэкенда, событие `publication.updated` → `queryClient.setQueryData` точечно.
- Права в UI — хук `useCan(action, resource)` по роли из `/me` (UI скрывает, но безопасность обеспечивает бэк).
- Feature flags — из `/me.features`.
- Все тексты интерфейса — в словарях i18n (без захардкоженных строк).

## 5. Дизайн-система (`frontend/packages/ui`) — сделать в Фазе 0

Каждый — в Storybook с a11y-аддоном и визуальными снапшотами.

## 7. Definition of Done для фронта
Компонент в Storybook; unit/компонентные тесты (Vitest + Testing Library) для логики и форм; e2e-сценарий в Playwright для пользовательского пути (с QA); нет ошибок axe; Lighthouse ≥ 90 (Performance, A11y) на ключевых страницах; тексты в i18n; поддержка тёмной темы и мобильного вида.
